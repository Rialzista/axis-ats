## Пошаговые задачи

1. **Единообразные состояния**
   - `EmptyState.tsx` — иконка/иллюстрация-заглушка + текст + опциональный CTA. Пройтись по всем местам,
     где сейчас "если данных нет — просто пусто" (Candidates list, Jobs list, Activity feed, Kanban
     колонка) и подставить единый компонент
   - `ErrorState.tsx` — для `isError` из TanStack Query, с кнопкой "Retry" (`refetch()`)
   - `Skeleton.tsx` — простые pulse-плейсхолдеры для `isLoading` вместо голого спиннера/пустого экрана
     (таблица со скелетон-строками выглядит на порядок профессиональнее)

2. **ErrorBoundary**
   - `app/ErrorBoundary.tsx` — React error boundary верхнего уровня, чтобы упавший компонент не ронял
     всё приложение в белый экран

3. **Адаптивность (базовый уровень)**
   - Sidebar сворачивается в иконки-only или в бургер-меню на ширине < 1024px — выбрать один подход и
     не усложнять
   - Таблицы: на маленьких экранах либо горизонтальный скролл контейнера, либо скрытие второстепенных
     колонок через `hidden md:table-cell` (Tailwind) — не нужно делать полноценную мобильную версию,
     макет Axis HRM сам по себе desktop-first

4. **Проверка тёмной темы на контраст**
   - Пройтись глазами по всем страницам, сверить с `design-tokens.md` — не должно остаться мест, где
     текст на фоне того же оттенка (частая проблема при копировании тёмных тем)

5. **README.md**
   - Что за проект, скриншот/gif Dashboard и Kanban, ссылка на оригинальный дизайн-концепт Axis HRM с
     указанием, что это источник вдохновения дизайна (а не автор — корректная атрибуция)
   - Как запустить локально (`npm install && npm run dev`)
   - Стек технологий (таблица из `00-overview.md` можно почти дословно перенести)
   - Явно указать: мок-бэкенд (MSW), данные не персистентны между перезагрузками (кроме того, что
     хранится в памяти MSW-воркера на клиенте)

6. **Деплой**
   - Собрать `npm run build`, проверить `npm run preview` локально
   - Задеплоить на Vercel или Netlify (connect GitHub repo — потребуется закоммитить проект в git,
     если ещё не сделано)
   - Проверить прод-сборку: роутинг на прямых URL (`/candidates/123`) не должен давать 404 —
     настроить rewrite/fallback на `index.html` в конфиге хостинга

7. **Storybook**
   - `npx storybook@latest init` — выберет React+Vite пресет автоматически
   - Истории (`*.stories.tsx`) для 5–8 компонентов `shared/ui`: минимум `Button`, `Card`, `Badge`,
     `StatusPill`, `Tabs`, `DataTable` (с мок-данными в story), по возможности `Avatar`, `SearchInput`
   - На каждый компонент — минимум 2 варианта (`args`/`argTypes` в Storybook Controls): например для
     `Badge` — разные цвета/размеры, для `StatusPill` — все статусы (`open`/`on_hold`/`closed`)
   - Не обязательно (но хорошо смотрится): включить `@storybook/addon-a11y` — он прогоняет ту же
     axe-проверку прямо в Storybook UI на каждый компонент, дополняя автотесты из пункта 8

8. **a11y — минимум**
   - Пройтись глазами по Kanban (клавиатурная навигация из Дня 5), формам (label/aria-describedby из
     Дней 3–4), проверить: фокус видим (`:focus-visible` не сброшен в CSS-ресете), icon-only кнопки
     (например, кнопки в Topbar) имеют `aria-label`
   - Установить `vitest-axe` (или `jest-axe` с адаптером под vitest)
   - `tests/a11y/dashboard.a11y.test.tsx` и `tests/a11y/candidates.a11y.test.tsx` — рендерят страницу
     (с обёрткой роутера/query-провайдера) и прогоняют `axe(container)`, проверяют отсутствие
     нарушений (`expect(results).toHaveNoViolations()`) — не нужно гнаться за 100% страниц, две
     ключевые достаточно как демонстрация подхода

## Критерии готовности

- [ ] Публичный URL открывается, все страницы работают без консольных ошибок
- [ ] Прямой переход по глубокой ссылке (например `/jobs/<id>`) работает после хард-рефреша
- [ ] Loading/Empty/Error состояния выглядят как продуманный UI, а не как "забыли обработать"
- [ ] README даёт незнакомому человеку полное понимание проекта за 2 минуты чтения
- [ ] Sidebar не разваливает layout на экране 1280px и уже — хотя бы минимально пригоден для просмотра
- [ ] `npm run storybook` поднимается, 5–8 компонентов задокументированы историями с несколькими вариантами
- [ ] `npx vitest run` зелёный, включая 2 a11y-теста через `vitest-axe`
- [ ] Фокус клавиатуры визуально виден на всех интерактивных элементах (не убран `outline: none` без замены)
