# Module Federation (Vite-native) — Фаза 4 (бонус)

## Статус: строго опционально

Делается **только если Дни 1–16 (Фазы 1–3) закрыты с запасом времени**. Это не часть основного плана —
если время поджимает, пропустить целиком без последствий для остального проекта.

## Зачем именно это, а не Webpack MF

У вас уже есть реальный production-опыт с Webpack Module Federation на Angular — повторение того же
самого паттерна на React ничего нового не доказывает интервьюеру: вопрос "делали ли вы MF" и так
закрыт честным "да" из вашего Angular-опыта.

Что действительно добавляет сигнал — показать, что вы в курсе, куда движется экосистема: команда,
придумавшая Module Federation (Zack Jackson), с 2023–2024 развивает **Module Federation 2.0** как
bundler-agnostic рантайм с официальными плагинами под разные сборщики, включая Vite
(`@module-federation/vite`) и Rspack. Большинство новых greenfield React-проектов уже на Vite/Rspack,
а не на Webpack — поэтому умение подключить MF именно в Vite-экосистеме, без второго сборщика в
монорепо, ближе к тому, с чем реально сталкивается React-команда в 2026, чем повтор classic Webpack MF.

## Что делаем

Выносим **Pipeline** (Kanban-доска, уже готовая с Дня 5 + realtime с Дня 16) в отдельное remote-
приложение, которое хост (основное ATS-приложение) подгружает динамически во время выполнения.

```
axis-ats/                          # host
  vite.config.ts                    # обновить: federation() plugin, remotes: { pipeline: ... }
pipeline-remote/                    # отдельный Vite-проект, remote
  vite.config.ts                    # federation() plugin, exposes: { './PipelineApp': ... }
  src/
    PipelineApp.tsx                 # точка входа remote-модуля, реэкспортирует существующий
                                     # KanbanBoard/PipelinePage из уже написанного кода (или копия,
                                     # если проще физически разделить репозитории — решить на месте)
```

Ключевое архитектурное решение, которое нужно принять до начала: **общий репозиторий с отдельным
Vite-проектом внутри** (монорепо, но не обязательно с Nx/Turborepo — можно просто два независимых
`package.json` в соседних папках) или **отдельный репозиторий** для remote. Для проекта проще
первое — меньше инфраструктурной возни, суть демонстрации (динамическая загрузка чужого бандла в
рантайме) не меняется от того, в одном репо это или в разных.

## Технические риски (почему это не входит в основной план)

- `@module-federation/vite` требует одинаковых major-версий `react`/`react-dom` в хосте и remote,
  объявленных как `shared` (singleton) — несовпадение версий даёт рантайм-ошибки, которые не всегда
  очевидны по сообщению
- Общие зависимости (React Router, TanStack Query context) должны либо шариться между host/remote
  через тот же `shared`-механизм, либо remote должен быть полностью самодостаточным по контексту —
  Pipeline использует TanStack Query (`useJobPipelineEntries`) и MobX-сторы, которые в норме живут в
  дереве хоста; передача контекста через границу MF требует явного протаскивания провайдеров или
  дублирования их внутри remote
- Dev-experience слабее, чем в обычном Vite HMR: приходится держать запущенными два dev-сервера
  (host на одном порту, remote на другом) одновременно

Из-за этого — реалистичная оценка 1–2 полных дня, а не "быстрый бонус на вечер", и именно поэтому это
Фаза 4, а не довесок к какому-то существующему дню.

## Definition of Done (если беретесь)

- [ ] `pipeline-remote` собирается и раздаёт `remoteEntry.js` независимо от хоста
- [ ] Хост динамически подгружает `PipelineApp` из remote во время выполнения (не на этапе сборки хоста)
- [ ] React/ReactDOM не задублированы в бандле (проверить через DevTools/Network — если задублированы,
  `shared` настроен неверно, будет два разных React-рантайма и вероятны баги с контекстом/хуками)
- [ ] Kanban внутри remote продолжает работать: drag&drop, realtime-обновления через SignalR (Фаза 3)
- [ ] Изменение в `pipeline-remote` и его пересборка отражаются в хосте без пересборки хоста целиком —
  это и есть основной "wow"-эффект Module Federation, который стоит явно продемонстрировать
